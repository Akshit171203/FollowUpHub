1. WHAT IS FOLLOWUPHUB?
================================================================================

FollowUpHub is a full-stack, real-time follow-up and task reminder management
system. It helps users track professional follow-ups (emails, calls, meetings,
Jira tickets, etc.) and personal to-dos, with an intelligent reminder engine that 
escalates overdue items and notifies users via in-app real-time notifications, 
email, and even Slack for critical tickets.


2. PROJECT GOALS
================================================================================

  • Build a personal CRM-style follow-up tracker so nothing falls through the
    cracks — every follow-up is tracked until resolved.

  • Intelligent Reminder Engine — automatic, policy-driven reminders with
    configurable escalation (from NORMAL → PERSISTENT → AGGRESSIVE) so overdue
    items become harder to ignore.

  • Real-time Notifications — instant in-app push via WebSockets (Socket.IO),
    plus email-based alerts so users are notified across channels.

  • Third-Party Integrations — fetch and sync tasks from external sources (e.g., Jira) 
    and push critical escalations to external channels (e.g., Slack).

  • To-Do Management — a lightweight daily to-do list with optional reminders,
    integrated alongside follow-ups for a unified productivity hub.

  • Reusable Templates — create follow-up templates (e.g., "HR Follow-Up",
    "Client Check-In") to quickly spawn new follow-ups from predefined patterns.

  • Email Templates — customisable HTML email templates for reminders,
    escalation notices, and digest emails.

  • Timeline & Audit Trail — every follow-up records a chronological event
    timeline (created, reminded, snoozed, escalated, done) for full traceability.

  • Dashboard & Analytics — a visual dashboard with charts (Recharts) showing
    follow-up statistics, overdue counts, and productivity insights.

  • Modern, Premium UI — a responsive, animated, dark-mode-capable interface
    with glassmorphism effects, micro-animations, and rich component design.

6. REMINDER ENGINE (CORE INTELLIGENCE)
================================================================================

  How It Works:
  1. A node-cron job runs every 60 seconds.
  2. It queries all active, non-DONE followups where dueAt < now.
  3. For each overdue followup, it checks cooldown:
     - NORMAL    → 60 min cooldown between reminders
     - PERSISTENT → 15 min cooldown
     - AGGRESSIVE →  5 min cooldown
  4. If the cooldown has elapsed, it sends a reminder notification
     (in-app via Socket.IO + optionally email).
  5. On every repeat reminder, ignoreCount increments.
  6. Based on ignoreCount thresholds, automatic escalation kicks in:
     - ignoreCount ≥ 1 → escalation level 1, LOW bumps to MEDIUM
     - ignoreCount ≥ 3 → escalation level 2, priority → HIGH, policy → PERSISTENT,
                          status → ESCALATED
     - ignoreCount ≥ 5 → escalation level 3, priority → URGENT, policy → AGGRESSIVE,
                          status → ESCALATED
  7. Each action is logged to the timeline (REMINDER_SENT, ESCALATED events).
  8. Manager & Slack Escalation — If a Jira-sourced ticket reaches Escalation Level 2+, 
     it dynamically triggers a Slack webhook notification and an email to the user's manager.

  Todo Reminders:
  - Runs after the followup engine in the same cron tick.
  - Simpler: no escalation, just sends a notification if remindAt has passed
    and cooldown has elapsed.


7. REAL-TIME NOTIFICATIONS (SOCKET.IO)
================================================================================

  - Server initialises Socket.IO with a Redis Adapter so it scales across
    multiple Node processes.
  - Auth middleware extracts JWT from cookies on WebSocket handshake.
  - Each user joins a room named by their userId.
  - When the notification service creates a notification, it emits to the
    user's room in real-time via `io.to(userId).emit()`.
  - Frontend connects via socket.io-client, listens for new notifications,
    and updates the notification bell and inbox live.

10. HOW TO RUN LOCALLY
================================================================================

  Prerequisites: Docker, Node.js (v18+), npm

  1. Clone the repo:
       git clone <repo-url>
       cd followuphub

  2. Start database and cache containers:
       docker compose up -d
     (Starts PostgreSQL on port 5434 and Redis on port 6379)

  3. Start the backend:
       cd backend
       cp .env.example .env   # configure your env vars
       npm install
       npm run dev            # runs on http://localhost:5001

  4. Start the frontend:
       cd frontend
       npm install
       npm run dev            # runs on http://localhost:3000

  5. Environment Variables (Backend .env):
       PORT=5001
       CLIENT_URL=http://localhost:3000
       DATABASE_URL=postgres://postgres:postgres@localhost:5434/followuphub
       REDIS_URL=redis://localhost:6379
       LOGIN_SECRET_KEY=<your-jwt-secret>
       SMTP_HOST=<smtp-host>
       SMTP_PORT=<smtp-port>
       SMTP_USER=<smtp-user>
       SMTP_PASS=<smtp-pass>
       GOOGLE_CLIENT_ID=<google-oauth-client-id>
       GOOGLE_CLIENT_SECRET=<google-oauth-client-secret>
       GITHUB_CLIENT_ID=<github-oauth-client-id>
       GITHUB_CLIENT_SECRET=<github-oauth-client-secret>
       SLACK_WEBHOOK_URL=<slack-webhook-url>

  6. Database migrations:
       cd backend
       npm run db:generate    # generate migration files
       npm run db:push        # push schema to database
